# DSE 最终结论与下一步决定

**本轮已完整完成：4720 次全网格数值执行 + 144 次胜者重复/新路由/计时敏感性执行，共 4864 次，全部通过。结果没有证明本次候选大小核优于强单核。**

| 固定方案 | 调参集相对单核耗时 | 未参与调参窗口相对单核耗时 |
|---|---:|---:|
| 同构双核 B4/K512 + B4/K512 | +3.40% | +2.69% |
| 等 PE 异形双核 B4/K512 + B2/K1024 | +5.03% | +4.62% |
| 大小核 B4/K768 + B2/K512 | +8.88% | +8.53% |

百分比按四个输入的几何平均计算。基线是同一网格内最优的固定单核 B8/K512；所有方案为 4096 个乘法器、相同 HBM、相同各项 SRAM 总预算。大小核分别为 3072/1024 个乘法器，各有独立 normal buffer 和 accumulator。

DSE 并非没有作用：旧大小核形状 B16/K192 + B8/K128 在同一网格内的最优配置是 p0968，几何平均 1.307645 ms；新形状为 1.041328 ms，耗时降低 **20.37%**。但与旧方案比较的改善，不能替代与强单核比较的收益证明。

## 为什么没有更快

1. **权重搬运量基本没有减少。** Qwen B8 的单核和新大小核都读取 60.162 MB。DeepSeek B8 从 166.265 MB 到 165.982 MB，只减少约 0.17%。已经按专家聚合的单核也能复用权重；多一个核心不会自动减少这些必要读取。
2. **空算减少不等于整个任务更快。** DeepSeek B8 的有效 MAC/发射 MAC 从单核 0.343 提升到大小核 0.628，但总耗时仍增加约 10.82%。供数、累加依赖以及双核完成时间的不均衡仍然存在。
3. **等待不全是 HBM Controller 的问题。** DeepSeek B32 小核记录约 0.996 ms 的权重就绪等待和 0.400 ms 的累加依赖等待。权重就绪包含取数、回包、解码和放入 SRAM 等路径；这些计数不能跨核心相加，也不能全部解释为 DRAM 排队。
4. **简单路径对照仍然成立。** 固定胜者在更宽/更窄的 activation 供数、查询流水 II=1、旧串行矩阵时序和省略查询/回包计时的乐观直通条件下，几何平均均没有反超同条件的固定单核。这些是固定胜者敏感性，未在每种假设下重做全网格搜索。

## 下一步决定

**保留 B8/K512 强单核基线，暂不冻结当前大小核作为性能更优的实现。** 后续按以下顺序验证，而不是继续增加 SRAM 或 HBM Controller 复杂度：

1. **先核准 accumulator 反馈和 SRAM 端口时序。** 当前模型把 `ceil(log2 K)+16` 的结果就绪约束用于同一输出块的后续 K tile。需要区分点积的前向流水延迟与真正的累加反馈依赖，核验是否存在合法的旁路或独立部分积排队；不能只改一个常数让候选获胜。实际端口/反馈契约与数值顺序必须先明确。
2. **再做有针对性的 tile 发射对照。** 当前固定 N tile → K tile → M block，可能让短 K 的核反复等待同一 accumulator。验证跨 N tile 交错发射能否隐藏等待，同时保持每个输出的 K 累加顺序、有限 SRAM/队列和端口约束。相同优化必须给单核和所有双核，先复测四类固定配置，再决定是否需要重新搜索。
3. **然后扩大负载和架构范围。** 引入真实训练权重、更多路由/模型、实际 batch/prefill 和输入输出 DMA 竞争。当前网格只覆盖列出的 BLEN/MLEN、两核、3:1 或 1:1 PE 组合及固定端口分配；BLEN=1、其他 PE 比例、矩形 M/N、逐核不同预取深度等都未搜索。
4. **会议后续事项继续保留。** 多小核、transpose buffer、attention/L-Compute 复用和完整 ISA/RTL 集成未在本轮完成。会议最后要求先验证 normal buffer + 独立 accumulator 的 MoE 对照，本轮完成的是这个阶段的数值搜索证据。
