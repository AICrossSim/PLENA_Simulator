# Qwen3 Fixed-Balanced Unscheduled + V4 Latency Report

**Integration status (2026-07-19):** The fixed-balanced path remains a
latency-only CostEmitter mode. Dense Qwen3-32B exhaustive DSE now additionally
uses compact layout, direct-first-block attention and compiler-v1
vector/scalar lowering; therefore its current 16.405 s result should not be
compared directly with the 36.281 s 512/64 benchmark below as though only the
model family changed.

## Scope

This report evaluates a latency-only fixed-balanced routing mode for Qwen3-235B-A22B. It avoids materializing 61,696 static route objects for a 482 x 16 prefill while retaining router, dispatch, expert, combine, and physical HBM costs. The native compiler and transactional emulator remain static-index only.

The common hardware configuration is MLEN=VLEN=512, BLEN=64, HLEN=128, M_LOAD=512, V_LOAD=V_WRITE=64, MXFP E4M3 block-8, 128 HBM channels, and CLOCK_PERIOD_PS=1000. Decoder totals exclude lm_head. Qwen3-32B uses 64 layers; Qwen3-235B uses 94 repeated balanced histograms.

## Estimator Design

For fixed-balanced MoE, route counts are generated by expert(token, rank) = (token * top_k + rank) mod num_experts. At the target shape this gives 61,696 routes, 128 active experts, 482 routes per expert, and 512 BLEN-padded rows per expert. Only the 128-entry histogram is retained; exact token addresses and runtime arg-topk are intentionally excluded. Repeating this histogram over 94 layers represents 5,799,424 decoder routes while still materializing zero Python route objects.

The fast latency estimate is:

```text
stage_latency = max(stage_compute_resource_work, stage_v4_memory_work)
total_latency = sum(stage_latency)
serial_upper_bound = total_compute_work + total_v4_memory_work
```

A stage is a compiler semantic region, not one kernel. Examples are `layer/attention`, `layer/ffn`, `layer/moe/router`, `layer/moe/experts`, and `layer/moe/combine`; each can contain many kernels and opcodes. Summing one `max(compute, memory)` value per stage treats stage boundaries as serial. The resulting stage-wise roofline is therefore not a mathematical lower bound on the scheduled program: legal cross-stage overlap can make it conservative, while unmodeled hazards can make it optimistic on other workloads.

Compute work uses the shared rtl-v1 opcode calibration. V4 memory work uses production DMA geometry. The fast path predicts one cold occurrence per geometry and scales its multiplicity. A global-row-state V4 pass is retained as a slower memory-only reference. Compressed Stage 2 replays ordered schedule repeats through the RTL scoreboard and is validation-only.

## Error Decomposition

| Model | Cached V4 vs global V4 | Roofline vs compressed Stage 2 | Serial vs compressed Stage 2 | Stage 2 wall (s) | Stage 2 RSS (GiB) |
|---|---:|---:|---:|---:|---:|
| qwen3-32b | 1.53% | 18.53% | 19.52% | 224.25 | 1.097 |
| qwen3-235b-a22b | 3.75% | 18.31% | 19.96% | 162.80 | 0.973 |

The cached-occurrence approximation changes one-layer V4 memory work by only 1.53% for 32B and 3.75% for 235B relative to the global-row-state evaluation. Both target cases are compute-bound, so the resulting stage-roofline change is much smaller than the memory-work percentage.

The stage-roofline estimate is 18.53% high for 32B and 18.31% high for 235B relative to compressed Stage 2. This is scheduler omission error: coarse stage boundaries do not preserve all cross-stage overlap. It is not an absolute RTL error measurement. The serial sum is, as expected, a slightly looser upper bound.

## Validation Evidence

1. **Route conservation and compactness.** Unit tests verify 7,712 tokens x top-8 = 61,696 routes, a per-expert difference no greater than one, BLEN padding, stable semantic hashing, and the absence of a route-object list in the aggregate summary.
2. **Static-plan parity.** A tiny Qwen3-MoE case compares fixed-balanced cost lowering with an explicit round-robin static plan. Dynamic opcode counts, per-stage opcode counts, and every compressed HBM event including geometry and multiplicity are exactly equal.
3. **Scheduler parity with observed DMA.** The existing Qwen3-32B 482 x 1 observed-DMA replay matches transactional makespan at 25,452,302 cycles with zero cycle/stall/resource delta when supplied the same DMA completion sequence.
4. **V4 generic holdout.** The production-DMA V4 holdout contains 585 samples: median error 3.48%, P95 18.10%, weighted MAPE 2.80%, maximum 42.18%, and store P95 19.92%.
5. **MoE transactional chain.** The existing Qwen3-235B seq=1 static-index run passes the unchanged numerical gate at 100.0% and reports 30.752 ms. Against that run, CostEmitter serial work differs by 1.57%, compressed Stage 2 by 14.19%, and the stage roofline by 16.42%.
6. **Focused regression.** The final dense CostEmitter, static-index MoE, fixed-balanced MoE, V4, and rtl-v1 scheduler suite completed 61 tests with no failures.

The seq=1 transactional case uses an explicit static expert set, not target-scale balanced routing. Equal-shaped experts make the cost invariant to expert IDs, and the tiny exact-parity test covers the round-robin aggregate transformation. No claim is made that balanced routing reproduces an input-dependent router distribution.

## Interpretation

Qwen3-235B has lower one-layer compute work than Qwen3-32B in this configuration because its active MoE width is top-8 x 1,536 = 12,288, below the dense 32B intermediate width of 25,600. Its 94-layer decoder estimate is nevertheless higher: 45.975 s versus 36.281 s at the 1 GHz conversion assumption.

For DSE, the stage-roofline estimate is fast enough for ordinary parallel trials and is preferable to compressed Stage 2, which took 163-224 seconds per one-layer validation. The observed approximately 18% conservative bias should be disclosed or corrected only after adding a held-out scheduler correction model; it should not be silently treated as cycle-exact latency.

## Limitations

- Fixed-balanced routing is a deterministic DSE assumption, not a prediction of real expert skew.
- Runtime arg-topk is excluded because no current PLENA RTL/ISA implementation exists.
- The 235B decoder repeats one balanced histogram across 94 layers and is marked approximate_repeated_balanced_routing.
- V4 is a post-hoc service model; cached occurrence and global row state are both reported explicitly.
- CLOCK_PERIOD_PS=1000 is a conversion assumption, not timing closure.
- Decoder totals exclude lm_head, and compressed Stage 2 is a scheduler reference rather than absolute RTL silicon validation.
