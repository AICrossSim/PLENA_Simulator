# M-DPU 纯计算评估报告契约

本轮是 DeepSeek-V2-Lite 的 Shared + 全部活跃 Routed 专家，65,536 个乘法器、1 GHz、BF16 输入与 FP32 累加、统一 OS、理想数据供给。阵列时序继承已有 PLENA 拓扑解析模型；它不是完整原版 PLENA RTL 的周期精确重现。

## 必须分开的三种比较

1. 用户指定的紧凑单核 / 对称双核 / Dense+Stream 家族比较。限制是实验条件，不能写成“PLENA 原生只支持 BLEN≥16”。
2. 相同几何能力的公平比较。若候选允许 PM=1/2 的流式子阵列，单核与同构也允许相同扩展；均使用相同控制器能力。
3. 固定硬件上的调度器消融。不能用换硬件后的加速比解释 M-DPU 的贡献。

全部选型只使用 18 个开发窗口。硬件与参数冻结后，用 135 个留出窗口报告 B2/B4/B8/B16/B64/B96/B128；综合指标是先取每 Batch 窗口几何平均，再取 7 Batch 等权几何平均。既往已探索的留出集不是新的盲测集。

## 数值与归因规则

- 每项指标从逐窗口机器可读结果生成；不预设异构一定胜出。
- 有效 GFLOP/s = 有效 FLOPs / makespan；MAC 利用率 = 有效 MACs / (65,536 × makespan cycles)。无效 padding 不计入有效 FLOPs。
- 纯阵列时间与包含控制器的完成时间分列；理想供数下预配置只能隐藏上下文准备，不能归功于隐藏 HBM。
- 窗口预测误差必须同一实际执行序列对齐。零误差的模型内估计不是对真实芯片精度的证明。
- 微操作队列深度、背压、决策周期、上下文准备周期、启动和完成事件可追溯；丢任务、重发、同核重叠均为错误。
- GFLOP/s、利用率和延迟几何平均使用同一窗口权重。动态阈值若不是严格分割边界，报告候选阈值和实际越轨数量，不能伪造单一阈值。
- 面积 / 功耗只有 PDK 综合或可校准模型才能给 mm² / mW。RTL 仿真、寄存器位数、逻辑统计不能当作实际面积功耗。
- 平均所需带宽与峰值端口需求是条件反推，不是已实现有限存储系统或端到端模型速度。

## 原论文核对

[PLENA v3](https://arxiv.org/html/2509.09505v3) 的 Table III 将 BLEN 搜索范围写为 2–64，MLEN/VLEN 为 2–1024；系统评估另用 BLEN=32、MLEN=2048、VLEN=2048。原生 PE 采用 MX 输入与整数累加；本轮 BF16/FP32 是明确的研究扩展。原论文已采用 OS、跨子阵列 M_SUM 和并行加载预取；本轮不能将“第一次实现计算与预取并行”当作贡献。

## 新颖性边界

[Gemmini 官方实现](https://github.com/ucb-bar/gemmini) 已含解耦加载 / 存储 / 执行队列、依赖管理及双缓冲循环控制。[Herald / Heterogeneous Dataflow Accelerators](https://research.nvidia.com/publication/2021-02_heterogeneous-dataflow-accelerators-multi-dnn-workloads) 已联合优化异构硬件分区与任务调度。因此双队列、比较器、预取、异构 DSE 本身不构成首次创新；本轮可验证的研究点应限定为真实 MoE 形状下、有限控制资源的派工规则及其相对于同能力基线的实测增益。完整相关工作检索与 PPA 尚需另行完成。
