# 在线派工修复：冻结评估契约

本任务只更改任务排序、核准入和预计等待时间。所有文件位于本目录，分支保持
`research/moe-supply-first-v3`。第二轮源代码、成本模型、窗口和结果保持原样。

## 硬件与输入

使用 E4 的完整冻结设计，包括数据流、私有容量、bank 和 vector 切分。
按用户补充确认，各模式沿用自己的 E4 硬件；`port_tight` 的 B2 是
`3×16×128` 两核，`pipelined` 的 B2 是 `2×24×128` 两核。
完整账本见 `frozen_designs.json`。

精度 BF16；总乘法器 12,288；总存储 2,158,592 B；共享 HBM 256 信用、
32 B 请求、64 周期返回延迟，理论供数上限 126.030769 B/cycle。
1 个假设周期等于 1 ns，ms=cycles/1e6。18 开发窗口和 135 留出窗口不变。

## 派工机制

每个候选描述符先计算各物理核的原始 `TaskCost`：

`refetch = hbm_bytes / unique_hbm_bytes`

此比值包括原模型已计算的重读和 spill；不人为改写各核的成本或字节数。
派工改变任务归属后，按原模型计算的总重读流量可以随之改变。
若当前可准入核的 refetch 大于 1，且另一物理核 refetch 等于 1，比较：

- 当前核可开始时刻＋其预测任务时长；
- 无重读核的预计空闲时刻＋其预测任务时长。

等待方案更早或相等时，当前绑定被拒绝。该描述符留在有限窗口内，其后其他
能准入的任务仍可绑定。立即执行方案更早时，按任务书允许重读执行。
若所有核都需要重读，该条件不触发，仍按预计完成时间选核。这尤其适用于
Shared B128：即使较大的 Z 缓冲也不能保存整个中间激活，不能把它误写成
无重读核。没有“永远给大核”的规则。

预计空闲时刻沿 Current 和已绑定 Next 累加，并计入 Next 的已知绑定授予
时刻；Current 的 ETA 使用既有预测器的进度反馈。ETA 不释放存储、不授予
资源、不提前满足依赖。实际执行仍使用原来的有限槽、端口和共享 HBM。

开启大任务排序时，Shared 或 `Me > T_big` 构成优先组；按所有合法核中最小
预测服务时长降序排列。其他任务保持原次序。排序只移动路由存储中的描述符，
不移动矩阵数据；候选窗仍为 8 项，每核仍最多 Current＋Next 两项。新增估计、
排序和比较操作在原有 1 操作/周期控制通路上计费。

## 参数与预测器

共同扫描 `T_big ∈ {2,3,4,6,8}` 和大任务排序开/关。对每个开发窗口先计算
各设计、各模式的 fixed/eft_old 配对延迟比，然后在 log 域等权平均，最后
对 18 个窗口取几何平均。只选一组参数供全部设计和两种模式使用。
200 次 bootstrap 以开发窗口为抽样单位，同一次抽样用于全部设计和模式。
关闭大任务排序时阈值不生效，相关等分数不得解释成阈值独立证据。

双核沿用第二轮原封不动的 `Predictor('ours')`：按原顺序预热 18 个开发窗口，
再连续测量 135 个留出窗口。每个重复使用独立初始状态，窗口内部顺序执行。
参数选择阶段从空状态跑一遍开发序列，再重置整序列重复。

原 E4 的 `eft_old` 没有学习预测器。因此另存 `eft_ours_control`，使用旧派工
和相同预测器算法及预热输入；不同派工产生的反馈状态可以不同，不能简单
相减称作完全独立的收益。单核直接委托原 E4 无预测器路径，确保逐位一致。

## 证据边界与验收

每个实际配置和整个学习序列重复两遍，比较完整结果的 canonical SHA256。
旧 EFT 和离线分配＋LPT 的 2,700 行对照重新生成，核对 E4 的原始周期与字节。
MILP/CP-SAT 解的是资源约束分配，LPT 是可执行参照，不是全局最优时序上界；
在线可以比该参照更快。

这是 post-router Gate/Up、SiLU、Down、combine 的 phase-fluid 解析估计，
不是 RTL、Ramulator 或整模型计时。不同资源占用时间可以重叠，不能相加。
验收分别检查：单核逐位不变、异构在线/离线 GM≤1.01、指定 GPQA 窗口延迟
和 HBM 流量均在离线 2% 以内、重复一致及测试通过。任何未达标项保留具体
差距和任务级原因，不换参数或窗口补成结论。

本轮仅评估是否修复在线与离线的差距，不据此宣布异构架构胜出。
