# 大Batch纯计算模型与复现约定

本轮的研究对象是完整 Shared + Routed MoE 专家计算。时间由可复现的分析模型给出；真实模型前向只负责提供真实路由，不用于冒充目标NPU的实测延迟。

## 数据与选型

输入为原始 DeepSeek-V2-Lite-Chat BF16 checkpoint 的真实前向。采用 BFCL 长提示词连续片段，另将多个独立 GPQA 请求的实际路由记录在 Router 之后打包。不存在合成路由、复制小Batch计数、或将不同请求拼成一个虚假的attention上下文。

请求ID哈希决定开发/留出归属与顺序，同一请求的重复归档只保留一次；之后按长度资格选样。每组2048个Token，取层2、13、26，各批次的连续切片起点由哈希决定。每个数据划分有5组（4个BFCL请求、1个GPQA路由打包组），共90个窗口。每批次15窗口；6个Batch等权。统计独立性以请求组为单位，不能将相关的90个窗口当90个独立请求。

选型目标为开发集每个Batch内窗口GM，再对6个Batch取等权GM。每种预算/模式/粒度的硬件选定后在所有留出Batch固定。最优同构由开发集在2/4/8/16核之间选择；异构也由开发集在2～16核之间选择。

## 共同几何空间

所有核的物理乘法器数为PM×PN×PK。PM={1,2,4,8,16,32,64}；PN={8,16,...,256}；PK={32,64,128,256,512}。核至少4096个乘法器且4096对齐。每个组织的总数严格等于预算。

两类组织都最多16核。相同核尺寸要求总预算能被核数和4096粒度整除，所以同构合法核数自然为2/4/8/16；异构保留3、5、7等合法组合。该扩展在任何正式DSE结果产生前冻结。

这个域是本研究声明的有限搜索域，绝不是已综合证实的1 GHz物理边界。特别是PN上限、单周期发射和跨核互连不收费，都属于待RTL/PPA验证的假设。

异构覆盖恰好两种不同几何组成的2～16核池。两种核各有至少一个，遍历其核数和所有合法整数算力切分。不限定Dense必须更大，也不预设3:1或1:1；输出保留实际几何、核数与工作占比。

## 计算时序

沿用第四轮的扁平点积阵列递推，不使用传统二维脉动阵列的K+M+N近似。

对一个投影，nM=ceil(M/PM)、nN=ceil(N/PN)、nK=ceil(K/PK)。Gate/Up成对的multiplicity=2，Down=1。点积与提交延迟L=3+2log2(PK)。拥有q个独立累加上下文的一组流水时间为：

```
group(q,nK,L) = (nK-1)*max(q,L) + (q-1) + L
```

OS保持8个输出tile上下文；WS按输出tile遍历M块；IS按M块遍历输出tile。具体整数递推由`model.py`给出，并逐项与第四轮原模型做回归。所有组织主模式均允许每个专家选择计算时延最短的OS/WS/IS循环顺序，理想局部存储且不计数据流切换。额外给出冻结硬件的统一OS对照；统一OS对照不是重新做OS最优硬件搜索。

有效MACs严格是3×M×2048×F，F为Shared的2816或Routed的1408。填充MACs不计入有效吞吐。整层利用率为有效MACs/(芯片物理乘法器×makespan)，包含负载不均衡和闲核损失。

完整专家模式对Gate/Up阶段计3MN个向量元素服务，对Down阶段计2MN个；同阶段矩阵与向量服务按理想流水`max`计算，两个阶段相加。向量吞吐按芯片每65536个乘法器配置64元素/周期，按核算力分配。固定64元素/周期对照保持芯片向量吞吐不随总算力扩大。此模型不含Router、Token重排、跨核通信或片上数据搬运。

## 调度最优性与完整枚举的含义

每个合法硬件配置在所有开发窗口上都计算：可行分配上界、单任务下界、可分割的双类型资源池分配下界。最大任务额外按“完整分配到类型A或类型B”两种情况取下界。整数优化使用精确周期和相同cost向量任务的计数变量，不做时间量化。

完整枚举不等于每个候选的NP难分配问题都精确求解。对有竞争力的候选进一步运行单线程、固定确定性工作额度的CP-SAT。报告中的组织搜索间隙定义为：

```
已找到的最佳可行开发GM / 全部候选开发GM下界的最小值 - 1
```

这个区间覆盖声明空间内未知的真正最优值。间隙为0才证明精确最优；非零时称“最优已找到解，最优性间隙x%”。开发集的搜索误差、留出集调度误差、bootstrap区间、以及硬件模型误差必须分开。

运行时对所有组织使用相同算法：Router完成后根据已知形状生成初始LPT顺序；保持该优先级，在队首8项内比较每个任务在所有核（包括暂时满队列的核）上的预计完成时刻。若最优目的核暂不能准入，允许等待，同时允许后续任务安全回填其他核，不能强迫任务溢出到慢核。每核Current+Next，描述符1周期/项，核配置2周期，可通过Next预配置隐藏。最初只比较可准入核并优先选择短任务的朴素版本也保留为诊断对照；通用准入修正不计作异构几何收益。这里没有实测控制器面积，也没有宣称新预测器已综合。

## 任务粒度

主对照把每个专家当作不可拆任务。另一个独立DSE允许Shared沿Token行切成最多64行的任务，各组织权限相同。每个行块拥有完整Gate/Up/Down依赖，MAC数严格守恒。不跨任务重复计算或遗漏路由专家。拆分涉及的真实跨核通信在理想供数模型中不收费，下一阶段必须补测。

## 复现

在仓库根目录，先用具备torch与transformers的环境运行：

```bash
python -m research.moe_dispatch.round5_largebatch_compute.capture --threads 8
```

再用numpy、scipy/OR-Tools、matplotlib、pytest及C++17/OpenMP环境运行：

```bash
OMP_NUM_THREADS=3 OPENBLAS_NUM_THREADS=1 python -m research.moe_dispatch.round5_largebatch_compute.run_all --workers 4 --refine 12 --work .08
python -m pytest research/moe_dispatch/round5_largebatch_compute/test_round5.py -q
```

运行器等待真实采集完整后生成窗口，枚举、冻结、留出评测、重复一致性检查、生成表格与审计。支持逐case断点续跑。没有自动git提交或push。
