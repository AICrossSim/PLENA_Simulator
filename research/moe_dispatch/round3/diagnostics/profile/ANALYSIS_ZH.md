# Sobol 全流程 CPU 诊断

诊断点为 `tau=15, bank=16, dot=2, credits=520, vector=1`；18 个开发窗口，五个族各 8 个候选、32 个节点。保留两次完整搜索，以及每个窗口的两次独立求解／物理回放，共 **2,880 次 evaluate_design**。诊断使用第二轮冻结硬件作为初始见证；正式 Sobol 仍需使用第三轮 E4 冻结硬件。

未插入 profiler 的同点冒烟耗时为搜索 agent 实测 236.36 s；cProfile 为 479.80 s。profiler 对小函数调用的干扰很大，下面比例用于定位，不能当成优化后的墙钟预测。

| 部分 | 累计时间 s | 总时间占比 | 解释 |
|---|---:|---:|---|
| 物理回放 | 238.61 | 49.7% | 全部 2,880 次仿真，未删任何重复 |
| 分配求解 | 206.45 | 43.0% | 每次都重新求解 |
| 几何初始排序 | 27.00 | 5.6% | 只依赖固定开发窗口与几何，不依赖 Sobol 参数 |
| 其中：CP 固定 T 求解 | 140.15 | 29.2% | 包含模型构造及原生求解 |
| 其中：精确枚举 | 61.15 | 12.7% | DFS visit 为 55.21 s，约 482 万次递归调用 |
| 其中：流体速率分配 | 97.92 | 20.4% | 644,140 次 `_fluid_rates` |
| 其中：dataclass 深复制 | 40.64 | 8.5% | 201,744 次 asdict；大量 phase 明细最终被 detail=False 丢弃 |
| 其中：CP 兼容别名构造 | 23.81 | 5.0% | 每个 CP 模型都重新构造旧命名方法别名，共 27,288 个模型 |

“其中”各行与前面主类别重叠，不能相加。原生 CP 求解本身为 34.11 s；因此只加速原生 solver 不能解决全部开销。

建议按风险从低到高进行，任何改动都必须维持完整候选数、节点预算、两次完整搜索和两次求解／回放，并比较完整结果摘要：

1. **不构造即将丢弃的输出明细。** `detail=False` 时不 append phase_rows/asdict。这些数据不参与速率、依赖、计费或派工，只在 detail=True 返回；为块化窗口处理保留需要的内部任务状态。其他观察字段及完整 detail=True 输出不变。
2. **缓存静态几何排序。** 缓存键必须包括整个开发窗口的相关维度／专家数量信息和族；排序结果与 tie 顺序保持不变。此项不缓存 solver 结果、owner 或仿真。每次独立求解仍运行。
3. **精确整数 DFS 使用本地代码。** 保留当前 Python 的系数构造、quantum 向下取整、分组、备选项顺序、suffix minima；仅执行同序同剪枝的整数递归。必须逐项一致地返回 owner、目标、nodes/leaves/pruned 与组计数。int64 的所有中间量先做界检查；不满足时回退 Python。不得改成不同遍历顺序的穷举／近似算法。
4. **减少 CP 模型别名重复创建。** 可在第三轮隔离 namespace 中使用固定的兼容 subclass，把 Add/NewIntVar/AddHint 等指向相同官方实现。保持生成的 CP proto、变量／约束顺序、hint、求解参数、每次新 solver、查询 trace 和确定性 work 完全相同。不可修改安装包或第二轮模块。
5. **谨慎优化 `_fluid_rates`。** 这是最大的单个物理热函数，但浮点 bit-exact 风险最高。可以预取固定 demand、权重和字符串 tie key，减少 dict 查找；必须保留 actor／resource 求和顺序、Python set 的实际迭代顺序、每一步舍入和 tie 规则。不要采用会重排浮点运算的 NumPy reduction、fast-math 或 FMA。先测试百万种有限状态及真实窗口完整摘要，再决定是否使用。

本诊断没有改变 model/runtime/optimizer/search/sensitivity/config。原始外围 manifest 检查捕获了同时发生的 evaluations/report 文档和独立诊断文件变动；这些未参与该搜索。完整 profiler 和两次搜索一致的证书已在检查触发之前保存，`finalize_profile.py` 对执行源文件的哈希重新核对并保留这次记录。
