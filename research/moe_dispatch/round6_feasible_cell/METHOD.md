# 第六轮实验契约

本轮时间属于**纯计算、假设普通操作数供给充足**的分析模型。主表保留矩阵递归、向量吞吐及额外 Shared 权重广播；不是有限 HBM、SRAM 端口齐全的端到端模拟，也不是 RTL 时序验证。

## 输入、预算与选择

- 第五轮原 90 个开发和 90 个留出窗口逐条复用。B4096 在同一划分内拼接两个不同 B2048 请求组的实际 Top-6 记录，增加各 15 个窗口；并非新做一次 B4096 attention 前向，也不复制同一 token 的路由。开发、留出请求不重叠。
- 每档预算上，S/H/H+/P/P+ 各自按开发集 **7 个 batch 等权、batch 内窗口 GM** 选择一套硬件；冻结后用于所有留出 batch。每 batch 独立开发选型只放附表。
- 几何继承第五轮：PM={1,2,4,8,16,32,64}，PN=8..256、步长8，PK={32,64,128,256,512}，单核 MAC 至少4096且按4096对齐。每专家独立选 OS/WS/IS 最小成本；矩阵＋按 MAC 数比例配置的向量吞吐为主口径。
- S、P、P+ 以及2/4/8/16核同构严格用满预算。12或13个相同合法核不可能恰好填满2的幂次预算，故枚举所有不超过预算的合法几何，单列未使用额度；利用率分母仍是整片预算，不把闲置额度抹掉。
- 每格的最强同构：比较**已冻结 H 和 H+ 硬件在该 batch 开发窗口的分数**，冻结组织选择后再看留出。离线和在线共用此分母；不根据留出窗口挑组织。附带报告 H/H+ 的完整数据供核对。

## Shared 分块、广播与驻留

H+/P+ 将 Shared 沿 token 行切为至多64行的块；每块完整执行 Gate、Up、Down，无跨块输出归约。不同核可能领取若干行块。Shared 权重只计一次片外读取；每个额外接收核产生33MiB片上复制流量。

普通供数理想化，而**额外 Shared 副本**通过全芯片同一个广播额度：默认10TB/s（每1ns周期10000B）。没有每核单独10TB/s。首份权重与未拆任务一致，属于原始理想供数；并非另收费后又算在广播里。5/20TB/s与无广播代价对照都使用同一规则。该选择与A判据的10TB/s数值相同，但两者概念不同：前者是复制端口额度，后者是原始权重平均供给的必要条件。

采用可复现的分块广播实现：256KiB一个块，Gate+Up共88块，Down共44块；每接收核两块缓冲。所有接收核对一个权重块用完各自的 Shared 行块，再推进下一块。Gate/Up结束后进入Down，存在共同阶段屏障。只做 routed 的核可从层开始并行；参与 Shared 的核在 Shared cohort 完成后推进 routed 队列。这是明确的共同流式广播契约，并不声称覆盖所有可能的广播网络/任意流水排序。

若有k个接收核，每权重块额外发送耗时 d=ceil(256KiB×(k−1)/(带宽×1000)) 周期。一个阶段有N块，接收核最大计算工作量为C周期，将C均匀分配到N个块（前C mod N块多1周期），双缓冲阶段耗时精确为：

`max(C+d, N*d+floor(C/N))`。

分块内计算均匀化是分析模型假设，已用独立双缓冲事件递推校验；不是声称每块实际指令流完全等长。正文必须注明此物理时序局限。

`peak_resident_MiB` 是实际时间线上的**权重缓冲峰值**：Shared每接收核2×256KiB，多接收核时加1个源块；routed每活跃核2×(PN×PK×2B)。不同专家的完整权重不会永久驻留。该数值不包括激活、累加器、队列，不能据此声称总SRAM只需这么大。

## 求解器、搜索和可复现性

全部有限几何候选都生成可行分配上界与严格下界；下界放松广播及整数任务约束，所以可偏松但不能超过真最优。CP-SAT 对开发集候选与冻结硬件留出窗口进一步求解包含广播的整数分配。计算预算使用确定性求解工作量，不使用墙钟超时。完整网格、精化点及在线点均重复两遍。

全局硬件搜索可能仍有残余最优性区间；各组织的 `dev_global_lower_cycles`、`dse_gap_pct` 公开。`offline_ms` 是可行上界，`offline_lb_ms` 是严格下界，二者不相等时不得称为精确最优。若在线生成了更好合法归属，将它也作为离线可行上界。

额外提供 `speedup_certified_lower=最强同构下界/异构可行上界` 和可能上界。A的保守校验使用异构计算下界反推带宽。这样可以区分“当前可行解达到10%”与“已排除求解误差后仍达到10%”。

大体量每候选逐窗口中间矩阵保存在 `/tmp/plena-round6-feasible-cache/`，提交全部可复算脚本、候选逐batch汇总、输入、冻结点逐窗口记录、摘要和哈希。

## 带宽、统计与判据

- 每激活 routed 专家有效BF16权重16.5MiB，Shared33MiB。`req_weight_TBps=唯一权重字节/周期/1000`。
- `req_total_TBps` 另加每专家 BF16 输入读和 FP32 输出写，即每token每专家6×2048B。这是明确的专家边界流量账本，未包含中间张量溢出、片上重复读取或Router访存，不可解释为完整实际HBM流量。
- 另列 `req_weight_and_replicas_TBps` 与 `req_boundary_and_replicas_TBps`，计入额外Shared副本。主A按用户定义仍只计唯一权重；A通过不保证原始供数和复制合用一条有限物理链路时也能通过。权重只读一次的平均带宽与小块缓冲容量是必要条件账本，不证明最优数据流在该容量下已经实现所有层级的一次读取。
- 主A使用已含广播时间的离线上界，可能因广播拖慢而降低平均带宽需求；为避免掩盖这一点，另报固定归属无广播计算速度下的需求及完全免广播对照。
- A10：权重需求≤10TB/s；A3.3：≤3.3TB/s。这里只是两档数值预算，不把3.3TB/s冒称某产品的实测规格。
- B：最强同构离线 / 异构离线≥1.10；C：最强同构在线 / 异构在线≥1.05，且异构在线 / 离线≤1.05。
- 每格使用该batch15个留出窗口的GM，所有速度比按配对窗口计算，等价于对应GM之比。峰值容量取该格最大值，不能用GM隐藏峰值。
- 200次稳定性分析在5个原始请求组上重采样；拼接窗口使用两个来源组抽中次数的平均权重，每batch归一化。它是保留来源相关性的加权bootstrap近似，不把新增拼接当独立请求。

等乘法器、相同广播额度不等于等面积或已经验证带宽可实现。A+B+C通过只能确定值得下一步有限端口/布局校准的候选格子。
