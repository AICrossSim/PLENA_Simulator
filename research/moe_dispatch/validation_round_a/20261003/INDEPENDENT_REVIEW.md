# Independent Round A v2 review

Status: credible prospective compute/vector hypothesis screening. No unresolved correctness blocker found for the declared ideal-operand model. This is not finite-memory E2E architecture validation.

Validation: 9 tests passed independently; all 864 development geometry/policy rows have exactly 12,288 main MACs; development-only EFT geometry argmins and subsequent threshold argmins were recomputed; all 1,215 selected heldout layer rows follow frozen selections; every summary total, p95, useful/issued MAC count, spatial/wall utilization and speedup was recomputed. One real captured mixed layer was independently replayed across all nine selected points. Input and source SHA256 pins match actual files. v3/mod.rs and compute.rs source pins also match immutable v10 build-manifest entries.

Resolved findings: equal-M/unequal-N cores were wrongly exempted from threshold routing in v1; fixed in v2 with a regression test and original artifacts retained. Captured-route provenance is now asserted, and coherent constructed routes are rejected. Source pins precede selection freeze and explicitly state the difference from the old eight-inflight-context projection oracle.

The closed-form projection accounts for tile ceil/padding, dependency on previous same-output K commit, independent record overlap and N-group retirement. The layer model schedules whole-expert queues, one shared vector engine, SiLU/product then Down then combination; global makespan includes queue contention. Geometry selection uses EFT on development only; threshold tuning follows geometry selection and also uses development only. Heldout is read after freeze and does not revise selections.

Remaining limits: new N widths are prospective and unsupported by the frozen Rust datapath. HBM, actual operand bandwidth, SRAM banks, paid dispatch service and numerical execution are absent. Minimum SRAM accounting is necessary-only, not proof of persistent Z/U/Combine residency, port feasibility or equal PPA. The prospective schedule permits up to eight N tiles times ceil(Me/PM) output records without the old separate eight-inflight cap, and explicitly says so. Dot20/II1/commit1/vector64 are inherited constants, not exact Rust timing equivalence. Historically exposed heldout remains non-blind; layer/prefix windows are correlated.

Results should be reported against the best development-selected single and homogeneous shapes, not only 6x4x512. Across 135 windows the best single 1x24x512 totals 25.023207 ms, best homogeneous 1x12x512 + 1x12x512 28.153740 ms, best asymmetric 1x2x512 + 1x22x512 25.323792 ms. Therefore asymmetric beats homogeneous but is about 1.20% slower than the searched single. Fixed 4+2 improves total time versus fixed 3+3 by 4.56%, but neither fixed shape is search-optimal. The hard threshold_1 rule for the selected asymmetry totals 54.467930 ms versus EFT 25.323792 ms: the naive cold-to-small rule is a negative result, not a predictor success.
